# Deploy the submission demo on Render

Use a **Web Service** to keep Sarvam voice working alongside the React app and local OCR. The supplied Blueprint describes one free Node service, with no database required.

The app server runs entirely on Render. Your laptop does not need to run a server or remain on. OCR runs inside the visitor's browser using assets served by Render; speech and transcription use the server-side gateway on Render.

## 1. Upload the source to GitHub

Use an existing GitHub account and create a repository, for example `presymp-kidney-map`. Private repositories work with Render; make it public only if the submission rules require public source.

If using the prepared `deployment/presymp-render-source.zip`, extract it first. Upload the extracted files and folders to the repository, not the ZIP. Check that `package.json`, `package-lock.json`, `render.yaml`, `.node-version`, `src/`, `server/`, `scripts/` and `public/samples/` are at the repository root. Keep `.gitignore` and `.env.example` too.

Never upload `.env` or any real API keys. `node_modules/`, `dist/`, `public/tesseract/` and local walkthrough recordings are not needed: Render installs dependencies and generates OCR assets during the build.

## 2. Deploy with the Blueprint

1. Open the [Render Dashboard](https://dashboard.render.com/) and choose **New → Blueprint**.
2. Connect GitHub, grant access to the repository, and select it and its branch.
3. Render reads the included `render.yaml`. Review the proposed free Web Service.
4. When prompted for `SARVAM_API_KEY`, paste the Sarvam key. It stays in Render's environment, outside GitHub and the browser bundle. Do not prefix it with `VITE_`.
5. Deploy and wait for the service to show Live. Open its `https://…onrender.com` URL.

The Blueprint path is configured as `dynamic-website/render.yaml` (or the repository root `render.yaml`), using `rootDir: dynamic-website`.

## Manual Web Service alternative

Choose **New → Web Service**, connect the same repo, and enter:

| Setting | Value |
| --- | --- |
| Runtime | Node |
| Root Directory | `dynamic-website` |
| Build Command | `npm ci --include=dev && npm run build` |
| Start Command | `npm start` |
| Health Check Path | `/` |
| Instance Type | Free |
| Environment: `NODE_ENV` | `production` |
| Environment: `HOST` | `0.0.0.0` |
| Environment: `SARVAM_API_KEY` | Your key |
| Environment: `NODE_VERSION` | `22` (also selected by `.node-version`) |

Leave `PORT` to Render. The server uses its supplied value. Include development dependencies in the build: TypeScript and Vite are required to produce `dist/`. No static-site Publish Directory is needed.

## Check the live link before submitting

- Open the app and a seeded patient; verify the map and source report viewer.
- Add a sample text PDF, phone photo and scanned PDF. OCR files are generated by `npm run build`.
- Open **Settings → Sarvam voice** and confirm the connection. With consent, try speech and a short transcription. Allow microphone access on the HTTPS site.
- Reload and confirm the app still loads. Kept recordings belong to that browser and site; localhost recordings do not transfer to the deployed site.
- Submit the HTTPS app URL and, if requested, the GitHub repo URL. Keep the supplied sample data for the public submission demo. This MVP has no clinic sign-in or shared cloud patient storage; anyone able to use the deployed voice gateway can consume its Sarvam credits.

Free Render Web Services sleep after 15 minutes without traffic and can take about a minute to wake up. Open the link shortly before a presentation and allow for that delay when sharing it with judges.
